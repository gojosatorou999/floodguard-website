Rules the scaffold enforces

These are structural, not stylistic. Breaking them means reworking later.

No hex literals outside tokens.css

The old site hardcoded one navy roughly 60 times and forced a white body background, which is exactly why it can't have a dark mode. Everything goes through semantic tokens. Worth adding a lint rule before real work starts.

#C1121F appears in exactly one component

The alert chip in LivePreview. It signals live flood state. It is never an accent, a hover, or a highlight.

Map geometry is a data asset, never code

IndiaChoropleth takes RegionMapAsset + RegionValues as props and knows nothing about India or where the data came from. One component serves the hero, the timeline's state map, and the Explorer preview. Real risk values wire in without touching any component.

Components stay presentational

No fetching inside components. Timeline state lives in FloodStoryTimeline so the bar chart and state map stay in sync while both children stay dumb.

Suggested order to start

Steps 1–3 aren't blocked by the missing assets. Step 4 onward is.

  1. Read STRUCTURE.md, then tokens.css

    Twenty minutes. The token layer is the thing everything else hangs off, and it's the one file that's finished.

  2. Self-host the three fonts

    Manrope (600–800), Inter (400–600), JetBrains Mono. As woff2 with @font-face — not a Google Fonts link. Subset to Latin. The stacks are already declared in tokens.css.

  3. Produce the India map asset

    Longest lead time, and nothing visual can happen without it. Spec and recommended approach are in src/data/geo/README.md. Pre-project and simplify offline — full-resolution district boundaries run to several MB; target under 300KB gzipped.

  4. Build Header and Footer

    Lowest risk, and they frame every other section. Dropdowns need click as well as hover, plus Escape-to-close — hover-only is an accessibility failure.

  5. Hero, then the rest in section order

    Hero is the highest-value section and exercises the choropleth, the stat bar, and the type scale in one go.

Decisions still open

  • Neutrals are derived. The supplied palette is ten blues plus the alert red — no greys. The --n-* and --ink-* values in tokens.css were derived with a blue bias to sit with the scale. Replace them if there are real ones.
  • The dark-mode choropleth ramp inverts. On a dark ground, high exposure has to read light or the worst districts vanish into the background. This is a behavioural change, not a colour swap — confirm it's wanted.
  • Where the helix goes. Built as components/motion/DitherHelix.tsx but deliberately not placed. The hero already has the choropleth, and two competing visuals in one hero is one too many. Three candidate slots are listed in the file; the strongest is replacing the static Explorer/Live product previews.
  • Form backend, real social accounts, and whether thefloodguard@gmail.com becomes hello@floodguard.in. All in README.md §12.

Separate and urgent

Live site — unrelated to the rebuild

floodguard.in is serving a Vite dev server in production. /@vite/client, react-refresh, and inline source maps are all publicly reachable, which means the complete unminified source is readable by anyone. That is how the current site's content was recovered for the audit.

Fix is roughly 30 minutes and doesn't wait on the rebuild: run npm run build and serve dist/ behind nginx, or move it to Vercel/Netlify. Worth doing this week.
